撰写任何供 agent 消费的文档的参考——一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、一份通过指针触达的文档。包装形式不同，写法不变：让每一份都可预测的是同一组杠杆——agent 每次运行走同样的_过程_，而不是产出同样的结果。

当你撰写的文档是一个 skill 时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式选择和路由 skill。

## 上下文指针

**上下文指针（context pointer）**是持有在 agent 上下文中的一个引用，它点名某份上下文之外的材料，并编码了触达它的条件。skill 的 description 是一个；`AGENTS.md` 中点名某份文档的一行也是同一个东西。决定 agent 何时触达材料——以及触达得多可靠——是指针的_措辞_，而不是它的目标。一个必不可少的目标躲在措辞软弱的指针后面，就是一个方差 bug（variance bug）：先磨砺措辞，只有在磨砺失败时才把材料内联进来。

一个指针做两份工作——说明材料是什么，并列出应当触发触达的**分支（branch）**（分支是文档处理的一个独立情形，因此不同的运行会走文档中的不同路径）。常驻加载的指针的每一个词在每一轮都要付费，所以它比正文更需要严格修剪：

- **把主导词放在最前**——指针正是它完成触发工作的地方。
- **每个分支一个触发词。** 为同一个分支改名的同义词是同一个分支写了两遍；折叠它们，只保留真正不同的分支。
- **删掉正文已承载的身份信息。**

## 两种负荷

你添加的每一份文档和指针，都在花费两种预算之一：

- **上下文负荷（context load）**——常驻加载材料对 agent 窗口的代价：一行 `AGENTS.md`、一条 skill description、任何每轮都待在上下文里的东西，无论是否触发都在消耗 token 和注意力。
- **认知负荷（cognitive load）**——对人类的代价：存在哪些文档、何时该取用哪一份。人类就是索引。这不是要最小化的代价——它是人类能动性的价格；在人类判断力重要的地方花它，在不重要的地方移除它。

只通过指针触达的材料以免除上下文负荷为代价，付出指针自身那一行；完全没有指针的材料则全部压在认知负荷上。

## 信息层级

一份文档由两种内容类型构成——**步骤（step）**（agent 按序执行的动作）和**参考（reference）**（按需查阅的定义、规则、事实）——两者可以自由混合：全是步骤（一份食谱）、全是参考（一次评审的规则、本 skill），或两者皆有。核心决策是每一块内容处于**信息层级（information hierarchy）**的哪一级——一架按 agent 需要该材料的紧迫程度排序的梯子：

1. **文件内步骤**——主层级：agent 要做什么，按顺序。
2. **文件内参考**——按需查阅。常常是正当的平铺同级集合（一次评审的所有规则在同一级）——这是一种不错的安排，不是坏味道。
3. **披露式参考（disclosed reference）**——推出去到单独的文件，通过上下文指针触达，只在指针触发时加载。跨度从同目录的兄弟文件，到位于任何地方、任何文档都能指向的完全外部参考。

推下去的太少，顶层就会臃肿；推下去的太多，你又把 agent 真正需要的材料藏了起来。这种张力就是整个决策。

**渐进式披露（progressive disclosure）**是沿梯子向下的移动——离开主文件，躲到指针后面——让顶层保持可读。它主要不是 token 优化：它是保护层级的方式。分支是最干净的披露测试：每个分支都需要的就内联，只有部分分支会触达的就推到指针后面。当一份文档有步骤时，本该披露出去的文件内参考会把步骤埋掉，让关注步骤变成抛硬币——这是一个方差杠杆，不只是可读性杠杆。

**同置（co-location）**是文件内的配套原则：梯子决定一块内容_往下放多深_，同置决定到位之后_谁与它相邻_。把一个概念的定义、规则和注意事项放在同一个标题下，而不是散落各处，这样读到其中一部分时自然会带出它的邻居。检验标准：文档读起来应当像为 agent 写的文档——成组的材料读起来是那样；散落的材料不是。（区别于重复：重复是同一个意思出现在两个地方；散落是一个意思碎在许多地方。）

**蔓延（sprawl）**是这里的失败模式：一份文档单纯地太长，即使每一行都是活的且唯一的。注意力在冗余中被摊薄，每多一行就多一行要保持相关的东西。解药是梯子：把参考披露到指针后面，并按分支或顺序拆分，让每条路径只携带它需要的东西。

## 步骤与完成判据

每个步骤都以一条**完成判据（completion criterion）**收尾——告诉 agent 工作已完成的条件。两个性质使它成为杠杆：

- **清晰度（clarity）**——agent 能否分辨完成与未完成？模糊的界限（"达成共识"）会招来**过早完成（premature completion）**：在工作真正完成之前就结束步骤，注意力滑向_已完成的状态_。前方仍可见的步骤——**后续步骤（post-completion steps）**——提供了拉力；判据的清晰度是阻力。按顺序防御：**先磨砺界限**（局部且廉价）；只有当它不可约减地模糊、_且_你观察到了仓促，才通过拆分序列把后续步骤藏起来——而藏匿只在真实的上下文边界上有效（一次交接或一次子 agent 派发；内联调用会把后续步骤留在上下文里，什么也清不掉）。
- **要求度（demand）**——它要求多少。"每个修改过的模型都有着落"会逼出彻底的工作，而"产出一个变更清单"不会。要求度驱动**跑腿（legwork）**——agent 在工作内部做的挖掘，潜藏在措辞中而不是写成自己的步骤——而且它不受步骤约束："每条规则都已应用"约束一摊平铺的参考，正如"每一步都已完成"约束一个序列，这就是一份纯参考文档仍然能承载彻底性门槛的方式。

最强的判据既可检验又无遗漏。

## 何时拆分

把一份文档拆成两份要花费两种负荷之一，所以只在切分值得时才拆：

- **按顺序拆**——在后续步骤会诱使 agent 仓促应付眼前这一步的地方，切开一串步骤。让它们离开视野能在当前任务上逼出更多跑腿。警惕反向操作：合并序列会把每一步的后续步骤暴露给后面的东西，招来过早完成。
- **按调用方式拆**——skill 特有：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 主导词

**主导词（leading word）**是一个已经活在模型预训练中的紧凑概念，agent 在运行文档时用它思考（_lesson_、_fog of war_、_tracer bullets_）。它以 token 形式重复，从不以句子形式出现，积累出一个分布式定义，用最少的 token 锚定一整片行为区域——靠的是征用模型已持有的先验。自己造词也行，只要你定义得清楚，但生造的词征用不到任何先验——你要用定义 token 支付一个预训练词免费提供的东西；优先使用现成的词。

它锚定两次。在正文中，锚定_执行_：agent 每次遇到这个词都会取用同样的行为，在平铺的参考内部它把注意力聚焦到一类要寻找的东西上。在指针中，锚定_调用_：当同一个词活在你的提示、你的文档和你的代码库中时，agent 会把这种共享语言与材料关联起来，更可靠地触达它。

主动寻找用主导词重构的机会。一个在三个地方拼写出来的三元组、一个花掉一整句去比划一个想法的指针——每一处都是乞求被折叠成单个 token 的段落：

- "fast, deterministic, low-overhead" → _tight_（一个 _tight_ 循环）。
- "一个你信得过的循环" → _red_——模糊的门禁变成一个二元的可观测状态（循环因这个 bug 变 _red_，或者没有）。

你赢两次：token 更少，agent 挂住思考的钩子更锋利。假定每份文档都背着可以被主导词退休的重述——去把它们找出来。

**否定（negation）**是这个杠杆旁边的失败模式：用禁令来引导会把被禁止的行为拖进上下文，让它_更_可得，而不是更不可得。_不要想大象_，大象就是全部；否定是一个弱修饰语，会被强烈激活的概念碾过去，于是禁令有一半读起来像一条照做的指令。提示**正面**——陈述目标行为（"写单行注释"），让被禁的那个从未被说出口。禁令只有作为无法正面表述的硬护栏时才配占一席之地；即便如此，也要与正面目标配对，让注意力落在该做什么上。

## 修剪

- 让每个意思只有一个**单一事实来源（single source of truth）**：一个权威的位置，这样修改行为就是一处编辑。**重复（duplication）**——同一个意思出现在多处——耗费维护和 token，并把这个意思在梯子上的显著度抬得超过它的真实等级。（主导词的意外反面：主导词刻意重复的是 token，从来不是意思。）
- **环境**也是事实来源——`package.json` 脚本、配置文件、目录布局、`--help` 输出——而重述它的文档是一个**缓存（cache）**：一份查找结果的拷贝，只在查找昂贵时才配占用负荷。缓存 agent 靠看找不到的东西：不成文的约定、选择背后的原因、没有配置会透露的坑。把一个文件、一条命令的查找留给环境，在那里它们不会过期。
- 检查每一行的**相关性**：它还关系到这份文档的职责吗？一行失去相关性，要么因为它从来与任务无关（纯粹的铺陈，或一个本该披露出去的分支），要么因为它描述的行为或世界变了而过期。更短的文档更容易保持相关。没有修剪纪律，默认命运是**沉积（sediment）**：过期的层不断沉降，因为添加感觉安全、删除感觉冒险，直到你必须向下钻穿它们才能找到还活着的东西。
- 逐句猎捕**空操作（no-op）**：一条模型默认就会遵守的指令，是花费负荷却什么也没说。检验标准——它相对默认行为是否改变了什么？——是相对模型的，不是相对读者的：两个人对一个 no-op 意见不合，是在对默认行为意见不合，用运行文档来裁决，而不是辩论。当一句话不及格，删掉整句，而不是从句子里删词。这个检验也给主导词打分：一个弱到赢不过默认行为的词（agent 已经相当彻底时的 _be thorough_）就是 no-op，修法是换一个更强的词（_relentless_），而不是换一种技术。
