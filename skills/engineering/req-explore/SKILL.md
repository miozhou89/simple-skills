---
name: req-explore
description: 通过不间断的访谈式追问打磨计划或设计，过程中同步产出文档（ADR 与术语表）。当用户想要压力测试自己的思考，或提出一个需求想法时触发。
---

围绕一个计划、决策或想法的所有方面对用户进行毫不留情的盘问，直到双方达成共识。将其映射为一棵 **设计树** (或称为 **决策树** )：每个决策都分支出挂在它之下的其他决策。

按 **轮次** 推进这棵树。**前沿（frontier）** 是所有前置条件均已敲定的决策——你 *现在* 就能问、无需猜测尚未听到的答案的问题。一轮内问完整个前沿：给每个问题编号并附上你的推荐答案，然后等待用户回答，再进入下一轮。

每个问题应按如下格式书写：

```
❓ **Q1** - **<question title>**: <question body, might be multiple paragraphs, including multiple choices>

➡️ <your recommended answer>
```

用户的每轮回答都会重塑这棵树——已敲定的决策把前沿向外推，解锁依赖它们的问题。重新计算前沿，提出下一轮。答案依赖本轮仍未决问题的问题，属于 *后续* 轮次，而非本轮。

查明 *事实* 是你的工作，永远不是用户的。当前沿问题需要从环境（文件系统、工具等）中获取事实时，派一个子 agent 去查——禁止向用户询问任何你自己能查到的东西。也不要为此阻塞：一次正在进行的探索是一项未决的前置条件，所以只有它下游的问题需要等子 agent 汇报——前沿上的其他问题现在就问。而 *决策* 属于用户——逐一提交给他们，然后等待。

当前沿为空时会话结束：设计树的每一条分支都已走过，没有任何东西被默默假设。在用户确认你们已达成共识之前，禁止据此采取行动。

达成共识后，依次使用 `/domain-modeling` 和 `/to-spec` skill。
