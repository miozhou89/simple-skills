# Ask Route

你记不住每一个 skill，所以来问。

**flow（流程）** 是穿越各个 skill 的一条路径。大多数路径沿着一条 **主流程（main flow）** 前进，另有两条 **入口匝道（on-ramp）** 汇入其中。其余的 skill 要么是独立的，要么是在底层运行的词汇层。

## 主流程：想法 → 交付

大多数工作所走的路线。你有一个想法，想把它做出来。

**整套流程（设计 → 规格 → 计划 → 实施 → 评审 → 维护）被编码为 `/ship`**——用户提出需求、要求方案设计或开发时模型会自动取用它，逐阶段路由到本页列出的 skill。你在那之下跟随即可；下面各步是这条主流程的具体形态。

1. **`/explore`** — 通过访谈打磨想法。只要你**在某个工作目录中工作**，就从这里开始：它是有状态的，会把学到的东西保存在 `CONTEXT.md` 和 ADR 中。
2. **分支——所有问题都能在对话中敲定吗？** 如果某个问题需要一个可运行的答案（状态、业务逻辑、必须亲眼看到的 UI），就绕道做一个原型，两个方向都由 **`/handoff`** 衔接（原型放在它自己的目录里，这正是 `/handoff` 的用途——见「阶段边界」）：
   - **`/handoff`** 出去，然后针对那个文件开一个新会话，
   - **`/prototype`** 用一次性代码回答这个问题，
   - **`/handoff`** 把你学到的东西带回来，并在最初的想法线程中引用它。

## 入口匝道

一种会产生工作的起始处境，随后汇入主流程。

- **有东西坏了** → **`/diagnosing-bugs`**。用于那些难缠的：看一眼无法定位的 bug、间歇性的 flake、在两个已知良好状态之间引入的回归。它拒绝在拥有**紧凑反馈循环**之前做理论推测——所谓紧凑反馈循环，就是一条已经能在*这个* bug 上变红的命令——然后用回归测试修复。当真正的发现是「没有好的 seam（接缝）可以锁定这个 bug」时，它的事后复盘会交接给 **`/improve-codebase-architecture`**。

## 代码库健康

不是功能开发——是保养。

- **`/improve-codebase-architecture`** — 一有空闲就运行，让代码库始终适合 agent 在其中工作。它会浮现**深化机会（deepening opportunities）**；选中一个就会_产生一个想法_，你可以带着它在 `/explore` 处进入主流程。它是负责找出候选者的勘测；**`/codebase-design`**（见下）是你在上面设计选中者的操作台。
- **`/performance`** — 性能分析与优化：数量级成本估算 → 剖析定位热点（pprof/perf/微基准）→ 应用优化技术 → 微基准验证。当用户要优化速度、资源或延迟，或问「哪里慢、怎么优化」时使用。若报告的是「最近变慢了」的回归，走 `/diagnosing-bugs`。

## 底层词汇层

两个 model-invoked 的参考 skill，在其他 skill *之下*运行——各自是其词汇的唯一事实来源。当问题在于**词语**而非流程时直接使用它们；或者让上面的 skill 自行引用它们。

- **`/domain-modeling`** — 打磨项目的*领域*语言：挑战模糊的术语，消解一词多义（"account" 同时承担三个含义），把难以逆转的决定记录为 ADR。它是 `/explore` 用来保持 `CONTEXT.md` 为一份干净词汇表的主动纪律。
- **`/codebase-design`** — 用于设计模块*形状*的深模块词汇（module、interface、depth、seam、adapter、leverage、locality）：在干净的 seam 处，用小接口承载大量行为。`/tdd` 和 `/improve-codebase-architecture` 都说这门语言。

## 阶段边界

**阶段（phase）** 是会话中的一块工作——访谈、实现、QA。在两者之间的**边界**上，你有五个选项，而在它们之间做选择是这整张地图里最模糊的决策：

- **Continue** — 原地不动。零成本，零损失。
- **`/handoff`** — 写一份可移植的 markdown 文件。适用面很窄：只用于**新 harness**、**新目录**、**同事**，或在**阶段进行中**分叉出一个支线任务。它换来的是可移植性。
- **Subagent** — 把一个范围收紧的任务送进它自己的窗口，拿回一份报告。
- **`/compact`** — 压缩当前上下文，用它给一个新会话做种子。这是**默认选项**，位于决策树的底部，而不是首选。

阅读 [PHASE-BOUNDARIES.md](PHASE-BOUNDARIES.md) 了解有序决策树——五个问题、每个分支背后的推理，以及为什么 primary-source 的代价让 **Continue** 成为要第一个排除的选项。决策要**在**边界处做；阶段进行中，要么继续，要么把剩余工作拆给 subagent。

## 独立 skill

完全在主流程之外。

- **`/explore`** — 探索和访谈：轮次、前沿、事实是 agent 的工作而决策是你的。`/improve-codebase-architecture` 也都在内部运行它。只有当你想要不带任何包装的访谈时才直接使用它。
- **`/prototype`** — 一个回答单个设计问题的一次性小程序：这个状态模型感觉对吗，或者这个 UI 应该长什么样。「一次性」是对代码写法的约束，而不是销毁它的承诺：答案会被折叠进真实代码，而原型本身作为 **primary source** 保留在 main 之外的 `prototype/<name>` 分支上，并从实现 issue 中指向它。它是主流程第 2 步中的绕道，但任何时候设计问题在纸面上难以敲定时都可以用它。
- **`/research`** — 把阅读的跑腿活委托给**后台 agent**：它对照 **primary sources** 调查一个问题，然后在 repo 中留下一份带引用的 Markdown 文件。它阅读时你可以继续工作。它产出的文件是要带*进*主流程 `/explore` 的东西——研究为思考提供养料，而不是取代思考。
- **`/teach`** — 跨多个会话学习一个概念，把当前目录用作有状态的工作区。
- **`/diagram-html`** — 把系统、流程、时序或状态的描述变成可缩放、可切主题、可导出 SVG 的单文件 HTML 图。无依赖无构建。

## 前置条件

**`/setup-simple-skills`** — 在你的第一个工程流程之前运行，配置其他 skill 所假设的 issue tracker、分诊标签和文档布局。自定义 issue tracker 同样可用。
