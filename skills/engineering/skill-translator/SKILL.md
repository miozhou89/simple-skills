# Skill Translator

把一棵文档目录树翻译成目标语言，产出结构逐文件对应的副本。读者是 AI 模型，译文必须是指令式、可精确执行的语言。

## 流程

先判断源是否已是目标语言：
- **已是目标语言** → 跳过翻译/复制/验证/Review，直接执行「阶段 6：精简」。
- **否则** → 按顺序执行阶段 1 → 6。

按顺序执行六个阶段：范围 → 复制 → 翻译 → 验证 → Review → 精简。

### 1. 确定范围

与用户确认：源目录、目标目录（默认 `<源目录名>-<语言代码>`，如 `skills-zh`）、目标语言、哪些文件类型要翻译（默认仅 `*.md`）。

用 `find <源目录> -type f` 列出全部文件，按扩展名分成两组：待翻译（`*.md`）与原样复制（其余全部）。

### 2. 原样复制非翻译文件

逐字节复制，保持相对路径：

```bash
cd <源目录> && find . -type f ! -name '*.md' | while read f; do
  mkdir -p "<目标目录>/$(dirname "$f")"; cp "$f" "<目标目录>/$f"
done
```

### 3. 并行分批翻译

文件超过 ~10 个时，按目录或大小分批，派多个 subagent 并行翻译（每批 10–20 个文件）。每个 subagent 的 prompt 必须包含：

- 源根目录、目标根目录、负责的相对路径清单
- 下方的「翻译规则」全文
- 流程：Read 源文件 → Write 到目标根目录下相同相对路径
- 自验证：每个文件 `grep -c '^```'` 与源一致

### 4. 验证

全部翻译完成后执行，四项必须全部通过：

```bash
# a. 文件清单一致（源与目标相对路径完全相同）
diff <(cd <源目录> && find . -type f | sort) <(cd <目标目录> && find . -type f | sort)

# b. 每个 md 的 frontmatter name 值未变
#    逐文件对比 grep -m1 '^name:' 的输出

# c. 每个 md 的代码块围栏数未变
#    逐文件对比 grep -c '^```' 的输出

# d. 非 md 文件逐字节相同
#    逐文件 cmp -s
```

发现 subagent 产生的临时文件（如 `.swp`）立即删除。

### 5. Review 润色

翻译完成后必须做第二遍 review（文件多时可再派并行 subagent，对照原文逐文件就地 Edit）。标准见「Review 标准」。

### 6. 精简

Review 完成后，对每个翻译产物执行一次技能精简（若源已是目标语言则直接执行）。标准见「精简标准」。精简后再通读一遍，确认无信息丢失。

## 翻译规则

只翻译自然语言说明：标题、段落、列表项、表格单元格内的说明文字、frontmatter 中 `description` 的值。

以下内容**原样保留，禁止翻译或改动**：

- frontmatter 的 key、`name` 的值、结构化配置的 key
- 目录名、文件名、skill 名称标识符（含正文和链接中以代码形式出现的，如 `ask-matt`、`/triage`）
- 代码块整体（``` 包裹的内容，含注释和字符串）
- 行内代码、命令、文件路径、URL
- package/tool/API 标识符与专有名词（TypeScript、GitHub 等保留英文）
- policy 保护词与行为关键 label（如 `disable-model-invocation`、`allow_implicit_invocation`、user-invoked、model-invoked）
- Markdown 结构：标题层级、列表缩进、表格、链接目标（链接文字可译）、HTML 注释

## Review 标准

译文读者是执行指令的 AI 模型，按以下标准收紧：

1. **指令式**：描述性、文学化、口语化的句子改为明确指令（"先 X，再 Y"、"禁止 X"、"仅在 Y 时 X"）。清除"尽量"、"可以的话"等含糊措辞和口语比喻。
2. **语气对齐原文**：原文 must/never/always → 必须/禁止/总是；原文 should → 应该。禁止加强或减弱语气。
3. **精简**：不改变主要意思的前提下删除冗余修饰和重复解释。原文存在的条件、约束、例外一条不许丢。
4. **术语一致**：先定一份全仓库术语表（哪些词保留英文、首次出现如何括注，如 "seam（接缝）"后文统一用 seam），交给每个 review agent 强制执行；完成后用 grep 全目录抽查残留（旧译法、中英混杂、口语词）。
5. **意思不变**：逐文件对照原文，不得丢失或新增信息。不确定时保留原文信息。

## 精简标准

目的：模型已内置的能力不必写在 skill 里，只保留模型真正需要指导的地方。对每个 SKILL.md 逐节判断其信息增量，删除增量为零的内容。

### 可精简（模型已内置）

以下内容对当前模型是标准行为或常识，信息增量为零，直接删除：

- **纯描述性内容**：概述、能力清单等与 frontmatter `description` 重复的段落。
- **通用工程最佳实践**：禁止硬编码值、遵循 WCAG、禁止 barrel import、tree-shake、懒加载、移动优先响应式、保持组件可组合——这些是模型默认行为。
- **自然流程步骤**：扫描代码库找已有组件、盘点资源命名、询问用户"是否符合预期"——模型会自然执行。
- **与主流程逐条重复的示例**：示例节若只是把工作流步骤复述一遍，整节删除。

### 必须保留（模型薄弱 / 非内置）

以下内容删除会丢失信息，必须保留：

- **非通用领域知识**：小众框架/工具的映射表（如 LVGL 的 `lv_conf.h` → `src/gui/`）、特殊配置约定。
- **模型易错行为的强约束**：禁止基于假设实现、禁止编造资源路径、禁止安装新依赖、禁止复制重复组件、复用优先。
- **校验清单**：对照设计稿/需求逐项验证的清单（交互状态、精确颜色、资源渲染等）——模型最常跳过验证步骤。
- **占位符策略**：资源不存在时用占位符 + 注释说明。

### 精简方式

- 直接删除冗余段落，或将自然可合并的小步骤压成一行。
- 保留所有条件、约束、例外与硬性语气（必须/禁止），只删冗余修饰。
- 精简后对照原文通读一遍，确认无信息丢失。

## 关键教训

- 翻译 subagent 只写目标目录，禁止碰源目录。
- 每个 subagent 的 prompt 必须自包含：规则全文 + 文件清单 + 验证命令，不依赖对话上下文。
- 术语表在 review 阶段开始前确定，所有 review agent 共用同一份，避免跨文件译法分裂。
- 精简只删信息增量为零的内容；模型薄弱点的强约束与校验清单是 skill 的最高价值，精简时一条不许丢。
