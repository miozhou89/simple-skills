# 逻辑原型

一个自包含的单 HTML 文件——一个**可分享的演示**——让任何人都能通过点击按钮来驱动一个状态模型。当问题关乎**业务逻辑、状态转换或数据形状**时使用——就是那种纸面上看起来合理、但只有推过真实案例才感觉不对的东西。

因为它是无需安装的单文件，你可以把它交给非开发者——设计师、PM、领域专家——让他们亲自感受这个模型。所以它说他们的语言，而不是代码的语言。

## 何时适用这种形态

- "我不确定这个状态机能否处理先 X 后 Y 的边界情况。"
- "这个数据模型真的能表达……这种情况吗？"
- "我想在动手写之前先感受一下这个 API 应该长什么样。"
- 任何有人想**按按钮、看状态变化**的场景。

如果问题是 "这个应该长什么样"——走错分支了。用 [UI.md](UI.md)。

## 流程

### 1. 陈述问题

写代码之前，先写下你要原型化的状态模型和问题。一段话，放在演示的顶部（在可见的引言里，不只是注释）。回答了错误问题的逻辑原型是纯粹的浪费——把问题写明确，以便日后检验，无论用户是现在在场还是离开后回来查看。

### 2. 把逻辑隔离进一个可移植模块

把真正的逻辑——回答问题的那部分——放进一个单独的 `<script>` 块，写成一个小而纯的模块，日后可以提出来放进真实代码库。它周围的页面是一次性的；这个模块不是。

正确的形态取决于问题：

- **一个纯 reducer**——`(state, action) => state`。当操作是离散事件、状态是单一值时合适。
- **一个状态机**——显式的状态和转换。当 "当前哪些操作是合法的" 是问题的一部分时合适。
- **一组作用于普通数据类型的纯函数**。当没有隐式的当前状态、只有转换时合适。
- **一个具有清晰方法面的类或模块**，当逻辑确实持有持续的内部状态时。

选择最贴合所问问题的形态，*而不是*最容易接到页面上的形态。保持纯净：不碰 DOM，不碰 `document`，按钮处理器不伸进它内部。页面调用它；反方向没有任何流动。这正是让原型在自身生命周期之外仍有价值的原因：问题一旦有了答案，验证过的 reducer / 状态机 / 函数集可以自行提升进真实模块。

### 3. 构建可分享的 HTML 文件

一个文件，纯 HTML/CSS/JS——不用框架，不用打包器，不用服务器，一切内联，双击即可打开，经得起邮件传来传去。任何人都应能通过打开它来运行。

为非开发者而写。每个标签都用**领域语言**，而不是代码——按钮和状态读起来像业务，而不是 reducer。用平实的话解释正在发生什么。

按清晰的层级从上到下布局：

1. **标题和一句话说明**这个演示能让你探索什么（第 1 步中的问题）。
2. **当前状态**——完整的相关状态，渲染成可读的面板（带标签的字段，而不是原始 JSON 转储），每次点击后重新渲染，让变化可见。在有助于非开发者理解的地方，标注刚刚变了什么。
3. **自由操作按钮**——每个操作一个按钮，始终可用，任何人都能按任意顺序戳弄模型。每次点击派发对应操作并重新渲染状态。
4. **引导演练**——一组**场景**，每个一个标签页。每个标签页放一段简短的场景平实描述——它设定的情境和该观察什么——下面是该场景要按的**有序按钮**。每一步都是一个真实按钮：点击它执行该操作并前进到下一步。开始一次演练会重置到已知的初始状态，使场景每次都以同样方式运行。

选择能演示尴尬情形的场景——正常路径、棘手的边界情况、一次理应非法的尝试——那些纸面上难以推理的情形。

保持美观但克制：干净的排版、大方的间距、一个强调色。不要动画，不要噱头——任何与状态和按钮争夺注意力的东西都不要。

### 4. 交付

把文件发给他们，或替他们打开。他们有空时会点完演练和自由操作；有趣的时刻是当他们说 "等等，这不应该可能发生" 或 "咦，我以为 X 会不一样"——这些是_想法_里的 bug，而这正是全部意义所在。如果他们想要新操作或新场景，就加上。原型会演化。

### 5. 留存答案与原型

原型回答了它的问题之后，留存答案，然后按 [SKILL](SKILL.md) 描述的方式留存原型。逻辑原型的具体映射：验证过的 reducer / 状态机 / 函数集提升进真实模块（决策被吸收）；HTML 外壳随之进入一次性分支，把原型作为 primary source 保存——作为单个自包含文件，它在那里依然可以毫不费力地重新运行。

## 反模式

- **不要加测试。** 需要测试的原型就不再是原型。
- **不要接真实数据库。** 除非问题专门针对持久化，否则用内存状态。
- **不要泛化。** 不要 "万一以后想支持 X 呢"。原型只回答一个问题。
- **不要把逻辑和页面混在一起。** 如果纯模块引用了 DOM、`document` 或按钮处理器，它就无法再被提升。让页面保持为纯模块之上的薄壳。
- **不要用框架、打包器或服务器。** 接收者双击打开的一个文件；React 应用或开发服务器会毁掉 "可分享"。
- **不要把 HTML 外壳带进生产。** 页面是为手动点击而优化的。它背后的逻辑模块才是值得保留的部分。
