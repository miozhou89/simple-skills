# 重新设计技能

## 运作方式

当应用于现有项目时，按以下顺序执行：

1. **扫描**——通读代码库。识别框架、样式方法（Tailwind、原生 CSS、styled-components 等）以及当前的设计模式。
2. **诊断**——过一遍下面的审计。列出你发现的每一个通用模式、弱点和缺失状态。
3. **修复**——在现有技术栈上应用有针对性的升级。不要从零重写。改进已有内容。

## 设计审计

### 排版

检查以下问题并修复它们：

- **到处都是浏览器默认字体或 Inter。** 用有特色的字体替换。好选项：`Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi`。对于编辑/创意项目，将 serif 标题与 sans-serif 正文配对。
- **标题缺乏存在感。** 增大展示文本的字号、收紧 tracking、降低 line-height。标题应该显得厚重且意图明确。
- **正文过宽。** 将段落宽度限制为约 65 个字符。增大行高以提高可读性。
- **只使用了 Regular（400）和 Bold（700）字重。** 引入 Medium（500）和 SemiBold（600）以形成更细腻的层级。
- **数字使用比例字体。** 为数据密集型界面使用 monospace 字体或启用表格数字（`font-variant-numeric: tabular-nums`）。
- **缺少 tracking 调整。** 大标题使用负 tracking，小型大写或标签使用正 tracking。
- **到处都是全大写的副标题。** 改为尝试小写斜体、句子式大小写或小型大写。
- **孤行单词。** 单个词孤零零地落在最后一行。用 `text-wrap: balance` 或 `text-wrap: pretty` 修复。

### 颜色与表面

- **纯 `#000000` 背景。** 替换为近黑、深炭灰或带色调的深色（`#0a0a0a`、`#121212` 或深海军蓝）。
- **过度饱和的强调色。** 保持饱和度低于 80%。对强调色去饱和，使其与中性色融合而不是刺眼。
- **超过一种强调色。** 选一种。去掉其余。一致性胜过多样性。
- **混用暖灰与冷灰。** 坚持一种灰色系。用一致的色调为所有灰色着色（暖或冷，不可两者皆有）。
- **紫/蓝 "AI gradient" 美学。** 这是最常见的 AI 设计指纹。用中性基底和一种经过斟酌的强调色替换。
- **通用的 `box-shadow`。** 为 shadow 着色以匹配背景色调。使用彩色 shadow（例如蓝底上的深蓝 shadow），而非低 opacity 的纯黑。
- **毫无纹理的扁平设计。** 为背景添加含蓄噪点、颗粒或微图案。纯扁平矢量显得乏味。
- **完全均匀的 gradient。** 用径向 gradient、噪点叠加层或 mesh gradient 打破均匀，而非标准的 45 度线性 gradient。
- **光照方向不一致。** 审计所有 shadow，确保它们暗示单一、一致的光源。
- **light mode 页面中随机出现的深色区块（或反之）。** 一个打破原本浅色页面的单一深色背景区块看起来像复制粘贴事故。要么全面采用 dark mode，要么全程保持一致的背景色调。若需要对比度，使用同一色板略深一档的色度——不要在米色页面中间突然跳到 `#111`。
- **空洞、扁平、没有视觉深度的区块。** 只是纯背景上文字的分区显得未完成。添加高质量背景图像（模糊、叠加或遮罩）、含蓄图案或环境 gradient。当没有真实 asset 时，使用 `https://picsum.photos/seed/{name}/1920/1080` 之类的可靠占位符源。在 hero 区块、特性块或 CTA 后方尝试背景图像——即使是一张低 opacity 的含蓄全宽照片也能增加存在感。

### layout

- **一切都居中且对称。** 用偏移边距、混合纵横比或居中内容上方的左对齐标题打破对称。
- **作为特性行的三等宽 card 列。** 这是最通用的 AI layout。替换为两列锯齿形、非对称 grid、水平 scroll 或瀑布流 layout。
- **为全屏区块使用 `height: 100vh`。** 替换为 `min-height: 100dvh` 以防止移动浏览器上的 layout 跳动（iOS Safari viewport bug）。
- **复杂的 flexbox 百分比运算。** 替换为 CSS Grid 以获得可靠的多列结构。
- **没有最大宽度容器。** 添加容器约束（约 1200-1440px）并配自动边距，使内容在宽屏上不会边到边拉伸。
- **被 flexbox 强制等高 card。** 当内容长度不一，允许可变高度或使用瀑布流。
- **所有元素统一的 radius。** 变化 radius：内部元素更紧凑，容器更柔和。
- **没有交叠或深度。** 元素扁平地并排。使用负边距创造层次和视觉深度。
- **对称的垂直内边距。** 上下内边距总是相同。进行光学调整——底部内边距通常需要略大。
- **仪表盘总是有左侧 sidebar。** 改为尝试顶部导航、悬浮命令菜单或可折叠面板。
- **缺少留白。** 将间距加倍。让设计呼吸。密集 layout 适用于数据仪表盘，不适用于营销页面。
- **card 组中的按钮没有底部对齐。** 当 card 内容长度不同，CTA 会落在随机高度。将按钮固定到每张 card 的底部，使其无论上方内容如何都形成干净的横线。
- **特性列表起始于不同的垂直位置。** 在定价表或对比 card 中，特性列表应在所有列中从相同的 Y 位置开始。在列表上方使用一致间距，或使用固定高度的标题/价格块。
- **并排元素中不一致的垂直节奏。** 将 card、列或面板并排放置时，跨所有项对齐共享元素（标题、描述、价格、按钮）。基线错位会让 layout 看起来破碎。
- **数学上对齐但视觉上看起来不对。** 按数学居中并不总是看起来居中。文本旁的图标、圆形中的播放按钮或按钮中的文字往往需要 1-2px 的光学调整才显得合适。

### 交互与状态

- **按钮没有 hover 状态。** 在 hover 时添加背景偏移、轻微缩放或平移。
- **没有激活/按下反馈。** 在按下时添加含蓄的 `scale(0.98)` 或 `translateY(1px)` 以模拟物理点击。
- **零时长的瞬时过渡。** 为所有交互元素添加平滑过渡（200-300ms）。
- **缺少焦点环。** 确保键盘导航有可见的焦点指示器。这是无障碍要求，不是可选项。
- **没有加载状态。** 用与 layout 形状匹配的 skeleton loader 替换通用圆形转圈。
- **没有空状态。** 一个什么都不显示的空白仪表盘是错失的机会。设计一个精心编排的"开始使用"视图。
- **没有错误状态。** 为表单添加清晰的行内错误消息。不要使用 `window.alert()`。
- **死链。** 链接到 `#` 的按钮。要么链接到真实目标，要么在视觉上禁用它们。
- **导航中没有当前页面指示。** 以不同样式呈现激活的导航链接，让用户知道他们在哪里。
- **scroll 跳动。** 锚点点击瞬时跳转。添加 `scroll-behavior: smooth`。
- **使用 `top`、`left`、`width`、`height` 的动画。** 切换到 `transform` 和 `opacity` 以获得 GPU 加速的平滑动画。

### 内容

- **"John Doe" 或 "Jane Smith" 之类的通用名称。** 使用多样、听起来真实的名称。
- **`99.99%`、`50%`、`$100.00` 之类的假整数值。** 使用有机、杂乱的数据：`47.2%`、`$99.00`、`+1 (312) 847-1928`。
- **"Acme Corp"、"Nexus"、"SmartFlow" 之类的占位符公司名。** 虚构符合语境、可信的品牌名。
- **AI 文案陈词滥调。** 禁止使用 "Elevate"、"Seamless"、"Unleash"、"Next-Gen"、"Game-changer"、"Delve"、"Tapestry" 或 "In the world of..."。用平实、具体的语言撰写。
- **成功消息中的感叹号。** 移除它们。要自信，不要喧哗。
- **"Oops!" 错误消息。** 要直接："Connection failed. Please try again."（连接失败。请重试。）
- **被动语态。** 使用主动语态："We couldn't save your changes" 而不是 "Mistakes were made."。
- **所有博客文章日期相同。** 随机化日期以显得真实。
- **多个用户使用相同的 avatar 图像。** 为每个不同的人使用独特的 asset。
- **Lorem Ipsum。** 禁止使用占位符拉丁文。撰写真实的草稿文案。
- **每个标题都使用首字母大写。** 改为使用句子式大小写。

### component 模式

- **通用 card 外观（边框 + shadow + 白色背景）。** 移除边框，或仅使用背景色，或仅使用间距。card 只应在层次（elevation）传达层级时存在。
- **总是一个实心按钮 + 一个幽灵按钮。** 添加文本链接或第三级样式以减少视觉噪音。
- **胶囊形 "New" 和 "Beta" badge。** 尝试方形 badge、旗标或纯文本标签。
- **accordion 式 FAQ 区块。** 使用并排列表、可搜索帮助或行内渐进式展开。
- **带圆点的 3 card carousel 证言。** 替换为瀑布流墙、嵌入式社交帖子或单条轮换引语。
- **三塔式定价表。** 用颜色和强调来突出推荐档位，而不仅是额外的高度。
- **一切都用 modal。** 对于简单操作，使用行内编辑、滑出面板或可展开区块，而非弹窗。
- **仅使用圆形 avatar。** 尝试超椭圆或圆角方形以获得不那么通用的外观。
- **Light/dark 切换总是一个太阳/月亮开关。** 使用下拉菜单、系统偏好检测，或将其整合进设置。
- **四列的 footer 链接堆。** 简化。聚焦主要导航路径和法务要求的链接。

### 图标

- **仅使用 Lucide 或 Feather 图标。** 这些是 AI 的"默认"图标选择。使用 Phosphor、Heroicons 或自定义图标集以形成差异化。
- **用火箭表示 "Launch"、盾牌表示 "Security"。** 用不那么明显的图标替换陈词滥调隐喻（bolt、fingerprint、spark、vault）。
- **各图标 stroke 宽度不一致。** 审计所有图标并统一为一种 stroke 字重。
- **缺少 favicon。** 总是包含品牌化 favicon。
- **图库 "多元团队" 照片。** 使用真实团队照片、抓拍或一致的插画风格，而非怪异的图库图像。

### 代码质量

- **Div 大杂烩。** 使用语义化 HTML：`<nav>`、`<main>`、`<article>`、`<aside>`、`<section>`。
- **行内样式与 CSS 类混用。** 将所有样式迁移到项目的样式系统。
- **硬编码像素宽度。** 使用相对单位（`%`、`rem`、`em`、`max-width`）实现灵活 layout。
- **图像缺少 alt 文本。** 为屏幕阅读器描述图像内容。禁止在有意义的图像上留 `alt=""` 或 `alt="image"`。
- **`9999` 之类的任意 z-index 值。** 在主题/变量中建立干净的 z-index 尺度。
- **被注释掉的死代码。** 发布前移除所有调试残留。
- **导入幻觉。** 检查每个导入确实存在于 `package.json` 或项目依赖中。
- **缺少 meta 标签。** 添加合适的 `<title>`、`description`、`og:image` 和社交分享 meta 标签。

### 战略性遗漏（AI 通常会忘记的）

- **没有法务链接。** 在 footer 添加隐私政策和条款链接。
- **没有 "返回" 导航。** 用户流程中的死胡同。每个页面都需要返回路径。
- **没有自定义 404 页面。** 设计一个有帮助、品牌化的 "页面未找到" 体验。
- **没有表单验证。** 为邮箱、必填字段和格式检查添加客户端验证。
- **没有 "跳到内容" 链接。** 对键盘用户至关重要。添加隐藏的跳转链接。
- **没有 cookie 同意。** 若司法辖区要求，添加合规的同意横幅。

## 升级技巧

升级项目时，从以下高影响力技巧中取材以替换通用模式：

### 排版升级
- **可变字体动画。** 在 scroll 或 hover 时插值字重或字宽，让文字显得鲜活。
- **stroke 到填充的过渡。** 文字以 stroke 轮廓开始，在 scroll 进入或交互时填充颜色。
- **文字遮罩显现。** 大型排版充当其后方视频或动画图像的窗口。

### layout 升级
- **打破 grid/不对称。** 有意无视列结构的元素——交叠、溢出屏幕，或以计算随机性进行偏移。
- **留白最大化。** 激进地使用留白，将焦点强加到单一元素上。
- **视差 card 堆叠。** 在 scroll 过程中钉住并物理堆叠在一起的分区。
- **分屏 scroll。** 屏幕两半向相反方向滑动。

### 动效升级
- **带惯性的平滑 scroll。** 将 scroll 与浏览器默认解耦，以获得更厚重、电影感的体验。
- **交错进入。** 元素以轻微延迟级联进入，结合 Y 轴平移与 opacity 淡入。禁止一次性全部挂载。
- **弹簧物理。** 用基于弹簧的运动替换线性缓动，让所有交互元素拥有自然、有重量的感觉。
- **scroll 驱动的显现。** 内容通过与 scroll 进度绑定的扩张遮罩、擦除或 SVG 路径描画进入。

### 表面升级
- **真正的玻璃拟态。** 超越 `backdrop-filter: blur`。添加 1px 内边框和含蓄内 shadow 以模拟边缘折射。
- **聚光边框。** 在光标下动态发光的 card 边框。
- **颗粒与噪点叠加层。** 一个固定的、pointer-events-none 的叠加层，带含蓄噪点以打破数字扁平感。
- **着色、带色调的 shadow。** 带有背景色相的 shadow，而非通用黑色。

## 修复优先级

按以下顺序应用更改，以获得最大视觉冲击和最小风险：

1. **字体更换**——最大的即时改善，最低风险
2. **色板清理**——移除冲突或过度饱和的颜色
3. **hover 与激活状态**——让界面显得鲜活
4. **layout 与间距**——合适的 grid、最大宽度、一致的内边距
5. **替换通用 component**——用现代替代方案替换陈词滥调模式
6. **添加加载、空与错误状态**——让它显得完成
7. **打磨排版尺度与间距**——高端的最后润色

## 规则

- 在现有技术栈上工作。不要迁移框架或样式库。
- 不要破坏现有功能。每次更改后测试。
- 在导入任何新库之前，先检查项目的依赖文件。
- 如果项目使用 Tailwind，在修改配置前检查版本（v3 与 v4）。
- 如果项目没有框架，使用原生 CSS。
- 保持更改可审查且聚焦。相比大重写，更倾向于小而有针对性的改进。
