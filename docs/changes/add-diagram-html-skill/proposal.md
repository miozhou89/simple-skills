# 提案：新增 diagram-html skill

## 问题

需要一种**不依赖任何构建期代码**的方式生成交互式 HTML 图表：skill 自身只有 `.md` 文件，没有 `.mjs`、没有 HTML 模板资产、不引入第三方依赖，产物是可直接打开的单文件 HTML。

现有的 `archify` 不满足这个约束——它把几何计算放在 Node 编译期，因此必须有 ~47k 行可执行代码与一个 728 KB 的 HTML 模板。

## 方案选择

几何计算只有三个可能的去处：

| 去处 | 上限 | 结论 |
|---|---|---|
| LLM 直接写坐标 | ~8 节点，极易错 | 否决：把最难的事交给最不擅长的一方 |
| CSS 布局引擎 | 分层/线性图，跨层连线做不好 | 否决：无缩放与导出，复杂拓扑退化 |
| **浏览器运行时** | 中等图、任意有向拓扑 | **采纳** |

选定浏览器运行时后，skill 的形态就确定了：**代码以 markdown 代码块形式内嵌**，由模型原样粘贴进产物。这既满足"只有 `.md` 文件"，又保留了完整的渲染能力。

副作用是模型必须被明确禁止改写这些代码块——"顺手优化"会破坏经过验证的几何假设。这是 `runtime.md` 与各布局参考开头的强措辞存在的原因。

## 收益

- 产物体积从 ~760 KB 降到 15–21 KB（无内联字体、无 CSS 内联导出逻辑）
- 模型单次需要创作的内容从"完整 IR 含坐标"降到"节点与边"
- 无依赖、无构建、无安装：把 `.md` 拷进 skills 目录即可用
- 导出 SVG 天然自包含，因为颜色已烤进属性

## 代价（明确接受）

- 无自动化测试与校验门——可靠性靠交付前自检清单与人工比对
- 布局不做避让与优化，长边绕行、密集处箭头重叠是可预期的
- 不做文字测量，超长标签截断为 `…`

## 不做的事

- 不替代 `archify`：需要校验门、源码证据、路由遮断、精美排版时仍用 `archify`
- 不引入 Mermaid 或任何图表库
- 不支持数值图表与仪表盘（那是 `chart-generator` 的职责）
